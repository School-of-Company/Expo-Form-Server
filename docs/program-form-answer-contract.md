# 프로그램 신청 답변 계약 (#113)

프로그램용 폼(`purpose=PROGRAM`)의 정의와, 신청 서비스(Expo-Application-Server#43)·Client(Expo-Client#345)가
제출하는 답변이 같은 약속을 쓰기 위한 문서다. Form 서비스는 답변을 저장하지 않고 폼 정의만 가진다.
답변 검증 규칙의 기준은 `src/json/answer-spec.schema.ts`의 `buildAnswerSchema`이고, 이 문서는 그 결과를
유형별로 풀어 쓴 것이다. 규칙이 바뀌면 `src/form/program-form-answer-contract.spec.ts`가 먼저 깨진다.

## 답변 모양

`{ "<문항 id>": <값> }` 하나의 객체다. 문항 id는 폼 조회 응답 `dynamicForm[].id`이고, 문자열 키로 쓴다.
폼에 없는 문항 id가 섞이면 거절한다(알 수 없는 키를 조용히 버리지 않는다). 필수 문항(`requiredStatus: true`)은
반드시 있어야 하고, 선택 문항은 생략할 수 있다.

| 유형 | 값 | 예 | 거절 |
|---|---|---|---|
| `SENTENCE` | 빈 문자열이 아닌 문자열 | `"오전 시간대 희망"` | 빈 문자열, 문자열 아님 |
| `CHECKBOX` | `true`/`false` | `true` | 문자열 `"true"` |
| `DROPDOWN` | `jsonData`의 키 하나(문자열) | `"1"` | 선택지에 없는 값 |
| `MULTIPLE` | `jsonData` 키의 배열, 1개 이상, `otherJson.maxSelection`이 있으면 그 이하 | `["1","3"]` | 빈 배열, 초과, 없는 키 |

값은 선택지의 **표시 문구가 아니라 키**(`jsonData`의 `"1"`, `"2"`)다.

## 프로그램용 폼에서 쓸 수 없는 것

폼을 만들거나 수정할 때 `400`으로 거절한다. 만들어 놓고 제출을 막는 것보다 관리자가 바로 알 수 있다.

| 항목 | 이유 | 풀려면 |
|---|---|---|
| `IMAGE` 필드 | 업로드를 맡는 서비스, 파일 참조 형태, 소유·행사 검증, 만료가 정해지지 않았다 | 업로드 서비스 계약 확정 후 `answer-spec.schema.ts`의 이미지 값 규칙과 이 문서를 같이 바꾼다 |
| `otherJson.hasEtc: true` | 기타 입력의 자유 입력값을 담을 모양·길이·조건부 필수 규칙이 정해지지 않았다 | 값 모양 확정 후 `DROPDOWN`/`MULTIPLE` 규칙을 바꾼다 |
| `COMPANION`, `REGION` | 신청(등록) 폼 전용 | - |

## 폼 변경과 답변

- 폼 조회 응답의 `version`은 수정할 때마다 1씩 오른다. 신청 서비스는 답변을 받을 때 **폼을 불러온 시점의
  `version`**을 함께 받아 현재 폼의 `version`과 다르면 거절해야 한다. 수정은 문항 id를 새로 발급하므로
  옛 폼 기준 답변은 문항 id가 맞지 않는다.
- 삭제된 문항은 위 규칙(없는 문항 id 거절)으로 걸러진다. 폼이 삭제됐으면 `404`다.
- 폼이 다른 박람회의 것인지는 폼 응답의 `expoId`로 신청 서비스가 확인한다.

## 정상·실패 예

폼 정의(요약): 1 `SENTENCE` 필수, 2 `CHECKBOX` 필수, 3 `DROPDOWN` 필수(`1`·`2`), 4 `MULTIPLE` 선택(`1`·`2`·`3`, 최대 2개).

```json
{ "1": "오전 시간대를 희망합니다", "2": true, "3": "1", "4": ["1", "3"] }
```

실패: 필수 누락(`"1"` 없음), `"3": "9"`, `"4": ["1","2","3"]`, `"2": "true"`, 없는 문항 `"99"`.
